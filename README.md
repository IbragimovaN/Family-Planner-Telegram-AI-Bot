# Family Planner

Прототип веб-приложения для семейных задач на React и TypeScript с сервером Express, базой SQLite и разбором текста через OpenAI API.

Текущая версия содержит тестовый функционал, созданный для проверки основной архитектуры приложения:

**интерфейс → сервер → база данных → OpenAI API**

Сейчас можно просматривать и добавлять задачи, переключать отметку выполнения и создавать несколько задач из сообщения с помощью AI. После этапа 1 база по умолчанию — `server/data/family-planner-v2.db`. Схема создаётся отдельной командой, при запуске сервера миграции автоматически не выполняются. Подготовлены таблицы будущего MVP; текущий прототип использует отдельную временную таблицу `prototype_tasks`.

## Подготовка

Нужны Node.js 22.12+ и npm. Из папки `family-planner-bot`:

```sh
npm ci
cd server
npm ci
cd ..
```

В `server/.env` укажите ключ OpenAI (нужен для запуска сервера):

```dotenv
OPENAI_API_KEY=your_openai_api_key
PORT=3000
DATABASE_PATH=data/family-planner-v2.db
DATABASE_BACKUP_DIR=data/backups
```

Относительные пути БД и резервных копий считаются от каталога `server`, независимо от текущей директории. При отсутствии переменных используются значения из примера. Секретный файл менять для этих значений не обязательно.

Один раз подготовьте пустую базу из корня проекта:

```sh
npm run build --prefix server
npm run db:init --prefix server
```

Команда сохраняет согласованную копию прежней `server/data/family-planner.db`, если она существует, затем создаёт новую пустую базу. Старые задачи не импортируются, исходный файл не удаляется. Если целевая база уже существует, команда откажется её перезаписывать. Перед переходом остановите старый сервер. Подробнее: [миграции и резервные копии](docs/DATABASE.md).

## Запуск для разработки

Сервер — в первом терминале из папки `family-planner-bot`:

```sh
cd server
npm run server-dev
```

Интерфейс — во втором терминале из папки `family-planner-bot`:

```sh
npm run dev
```

Откройте `http://localhost:5173` (или адрес из вывода Vite). Сервер работает на порту `3000`.

## Сборка и запуск

Из папки `family-planner-bot` после подготовки:

```sh
npm run build
cd server
npm run build
npm run db:migrate
npm start
```

Откройте `http://localhost:3000`.

## Проверки

Из корня проекта:

```sh
npm run lint
npm run build
npm run build --prefix server
npm run typecheck --prefix server
npm test --prefix server
```

Тесты БД работают с временными базами и требуют предварительной сборки backend. Секреты и реальные данные для них не нужны.

## API и AI

| Метод и путь                  | Назначение                                                                      |
| ----------------------------- | ------------------------------------------------------------------------------- |
| `GET /api/health`             | Проверка доступности сервера                                                    |
| `GET /api/tasks`              | Получение списка задач                                                          |
| `POST /api/tasks`             | Создание задачи из JSON`{"title":"Купить молоко"}`                              |
| `PATCH /api/tasks/:id/toggle` | Переключение отметки выполнения                                                 |
| `POST /api/ai/tasks`          | Разбор JSON`{"text":"Купить молоко и позвонить врачу"}` в список названий задач |

AI-обработчик возвращает `{"tasks":["..."]}` и сам не сохраняет задачи. Интерфейс затем создаёт каждую задачу отдельным запросом `POST /api/tasks`.

Модель задана в `server/src/ai.ts` строкой `gpt-5.6-luna`; переменной окружения для её выбора нет. Для работы AI необходимы действующий ключ и доступ к указанной модели. Успешная сборка не подтверждает доступность модели или корректность ответа внешнего API.
