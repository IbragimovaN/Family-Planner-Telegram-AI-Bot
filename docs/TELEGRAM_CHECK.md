# Авторизация и приглашения в Telegram

Каждый новый запуск страницы с initData сначала подтверждает подпись и свежесть на сервере, затем читает профиль. Старая cookie не выбирает аккаунт вместо Telegram. При смене аккаунта прежняя сессия в этом браузере заменяется. При перезагрузке страницы с initData старше 5 минут нужно закрыть Mini App и открыть заново; работа уже открытой страницы продолжается по сессии.

Предпросмотр приглашения: POST /api/family/invitation-preview, JSON {token}, только после входа. Возвращает название и membership: none/same/other. Не раскрывает участников и не создаёт членство. Вступление заново проверяет срок и отзыв ссылки, поэтому отзыв между просмотром и нажатием тоже учитывается. Кнопка «Поделиться в Telegram» открывает выбор чата; пользователь сам подтверждает отправку. Копирование остаётся доступным.

В разделе участников/настроек есть «Сообщения от бота». Запрос разрешения вызывается только нажатием пользователя. Отказ не блокирует приложение. Флаг SDK используется лишь для интерфейса, не как серверное подтверждение права отправки. Планировщик уведомлений ещё не реализован; при его реализации нужно учитывать актуальную доступность бота, обновления Telegram и ошибки отправки. Ежедневная рассылка этой доработкой не включается.

## Caddy и лимиты входа

По умолчанию заголовки прокси не считаются доверенными. TRUSTED_PROXY_IPS принимает только конкретные IP-адреса через запятую, не true и не количество переходов. Укажите адрес Caddy, который Express реально видит как адрес TCP-соединения. Для Caddy на хосте и приложения в Docker это может быть адрес шлюза Docker, а не 127.0.0.1. Определите его при развёртывании, не подставляйте пример вслепую.

Порт приложения должен оставаться недоступным извне. Caddy должен формировать корректный X-Forwarded-For и не доверять произвольным входным заголовкам клиента. Если добавляется CDN, отдельно настройте и проверьте всю цепочку доверия. В таком окружении лимит применяется по клиентскому IP, а не совместно ко всем пользователям Caddy. Локальный тестовый вход по-прежнему запрещён через прокси.

## Проверка после развёртывания

1. Настроить Main Mini App в BotFather, APP_ORIGIN, TELEGRAM_BOT_TOKEN и TELEGRAM_BOT_USERNAME на сервере. Секреты не отправлять в чат.
2. Открыть приложение первым аккаунтом Telegram, затем вторым: имя и данные должны соответствовать текущему аккаунту. Проверить Android, iOS и Desktop/Web, включая сохранение cookie.
3. Создать приглашение, нажать «Поделиться в Telegram», выбрать получателя. У нового участника до вступления видны название семьи и подтверждение, после — главная.
4. Проверить ссылку участником той же семьи, другой семьи и аккаунтом без семьи. Отозвать ссылку и проверить запрет вступления, в том числе после уже открытого предпросмотра.
5. В «Сообщения от бота» проверить отказ и согласие. Не ожидать ежедневных уведомлений до реализации соответствующего этапа.

Локально прошли 27 серверных тестов, сборки и lint; в браузере с имитацией SDK проверены порядок авторизации, предпросмотр, вступление, три состояния ссылки, открытие отправки и ответы на запрос разрешения. Реальный Telegram и VPS требуют отдельной проверки выше.
