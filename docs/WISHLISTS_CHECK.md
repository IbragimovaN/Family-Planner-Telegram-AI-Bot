# Этап 8 — общие семейные вишлисты

Реализован локально в ветке `step8`, 16 октября 2026. Раздел открыт с главной кнопкой «Вишлисты». Внешний вид повторяет покупки: пастельная панель на доступную высоту, компактные строки, отдельная прокрутка, двухстрочные названия, переключатель скрытия исполненных, карандаш и корзина.

## Поведение и права

- Для создания требуется только имя. Оно хранится текстом и не связывается с аккаунтом или участником семьи.
- Все участники семьи, включая новых, видят все её вишлисты. Вступление не создаёт вишлист автоматически.
- Любой участник семьи может добавлять, редактировать, удалять желания и отмечать исполнение. Выполненные желания можно вернуть; порядок строк сохраняется.
- Создатель вишлиста и владелец семьи могут переименовать или удалить его. Удаление требует подтверждения и удаляет связанные желания.
- Название желания обязательно; ссылка, заметка и цена необязательны. Цена хранится целым числом минимальных денежных единиц; интерфейс принимает точку и запятую, поддерживает RUB/USD/EUR.
- Ссылки разрешены только HTTP(S), без логина и пароля в URL. Они открываются с `noopener noreferrer`; сервер не загружает содержимое ссылок.
- Данные обновляются после действий, при возвращении к вкладке и раз в 15 секунд. Ошибка сохранения не закрывает форму и не очищает введённое.

## Файлы и данные

`server/src/wishlists.ts` — API и права; `src/Wishlists.tsx` — интерфейс; `src/components/FormDialog.tsx` — формы в диалогах. Маршруты подключены в `server/src/app.ts`, `src/navigation.ts` и `src/FamilyGate.tsx`. Стили — `src/App.css`.

Используются `wishlist_profiles` и `wishlist_items` из миграции 1. Новая миграция не требуется, существующие миграции не изменены. `created_by_user_id` служит для авторства и прав, а не для связи человека из имени с аккаунтом. Docker, volumes и производственные данные не изменялись.

## API

Все маршруты требуют сессии и членства в семье. Мутации проходят существующую проверку Origin, JSON и заголовка `X-Family-Planner: 1`. Семья определяется сервером.

| Метод и путь | Данные |
| --- | --- |
| GET `/api/wishlists` | `{profiles}`: имя, счётчики и `canManage` |
| POST `/api/wishlists` | `{name}` → 201 `{id}` |
| GET `/api/wishlists/:id` | `{profile, items}` |
| PATCH `/api/wishlists/:id` | `{name}` → 204, создатель или владелец семьи |
| DELETE `/api/wishlists/:id` | `{}` → 204, создатель или владелец семьи |
| POST `/api/wishlists/:id/items` | `{title, url?, note?, priceMinor?, currency?}` → 201 `{id}` |
| PATCH `/api/wishlist-items/:id` | Поля желания и/или `completed` → 204 |
| DELETE `/api/wishlist-items/:id` | `{}` → 204 |

Цена и валюта передаются вместе либо обе равны null. Название — до 200 символов, имя — до 100, заметка — до 2000, URL — до 2048. Чужие идентификаторы возвращают 404, недостаточные права на свой семейный вишлист — 403. Автор и время исполнения записываются атомарно; повторная отметка не перезаписывает автора.

## Проверки

```powershell
npm.cmd run build
npm.cmd run lint
npm.cmd --prefix server run build
npm.cmd --prefix server test
node scripts/check-wishlists-browser.mjs
```

Пройдены 54 серверных теста. Новые тесты в `server/test/wishlists.test.mjs` проверяют общую видимость, отсутствие автоматических профилей, права автора и владельца, изоляцию семей на всех маршрутах, удалённого участника, CRUD, исполнение/возврат, каскадное удаление, URL и цену.

Браузерный сценарий использует временную базу в памяти и имитацию Telegram SDK: создание по имени, полный редактор, цена с запятой, стилизованный выбор валюты, отметки, фильтр, переименование, Telegram BackButton, перезагрузка, отмена удаления и удаление с подтверждением. Ширины 320/375/430/880 px, скриншоты в игнорируемой `.checks.local`.

Проверка на настоящих устройствах Telegram и развёртывание на VPS не выполнялись. Коммит и push требуют отдельного разрешения пользователя.
