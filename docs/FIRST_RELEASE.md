# Первый релиз: этапы 1–3

Локальные функции готовы к проверке; выполнение команд на VPS требует подтверждённых SSH-реквизитов, пути checkout, текущего имени Compose-проекта/тома и расположения Caddy. Эти параметры нельзя угадывать: другое имя Compose-проекта подключит новый том вместо существующего.

## Перед обновлением

1. Проверить локальные lint, build frontend/backend, typecheck и тесты. Зафиксировать изменения в Git.
2. На VPS определить текущий commit, Compose project, volume `server-data`, источник .env и reverse proxy. Записать их для отката.
3. Остановить приложение и создать резервную копию существующих данных и `server/.env` вне контейнера; для SQLite использовать согласованный backup с учётом WAL. Не выводить значения .env в терминал/логи и не добавлять backup в Git.
4. Получить проверенный commit, сохранив прежнее имя Compose-проекта.
5. Настроить `NODE_ENV=production`, `DEV_AUTH_ENABLED=false`, `APP_ORIGIN=https://planner-bot.ibragimova-apps.ru`, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_BOT_USERNAME`. Ключ OpenAI нужен только для AI-кнопки.

## Сборка и база

Из подтверждённого каталога проекта на VPS (те же параметры `-p`/compose-файлы, что у действующего сервиса):

```sh
docker compose build app
```

Если `family-planner-v2.db` ещё отсутствует:

```sh
docker compose run --rm --no-deps app npm run db:init
```

Эта команда дополнительно делает backup прежней базы, не импортирует старые задачи и не перезаписывает существующий целевой файл. Если новая база уже существует:

```sh
docker compose run --rm --no-deps app npm run db:migrate
```

При ошибке миграции запуск не продолжать. Удаление тома через `down -v` не используется.

## Caddy и порты

Compose теперь публикует `127.0.0.1:3000:3000`; порт приложения не должен быть доступен извне. Для Caddy на хосте upstream — `127.0.0.1:3000`. Пример блока для объединения с существующим Caddyfile, а не замены его целиком:

```caddyfile
planner-bot.ibragimova-apps.ru {
    reverse_proxy 127.0.0.1:3000
}
```

Если Caddy запущен в Docker, нужна подтверждённая общая Docker-сеть и upstream `app:3000` без публикации порта наружу. Не применяйте пример для хостового Caddy внутри контейнера. Сначала проверить фактическую конфигурацию, затем валидировать и перезагрузить Caddy.

## Запуск и приёмка

```sh
docker compose up -d app
docker compose ps
docker compose logs --tail=100 app
```

Проверить HTTPS `/api/health` (200), анонимный `/api/me` (401), отсутствие dev-входа, запуск Mini App из бота, правильного пользователя, семью/приглашение двумя аккаунтами, logout и перезапуск контейнера без потери данных. Убедиться, что секреты и initData не попадают в логи. Уведомления относятся к этапу 9 и сейчас не проверяются.

Проверка через браузер описана в [FAMILY_CHECK.md](FAMILY_CHECK.md), Telegram — там же и в [AUTH_CHECK.md](AUTH_CHECK.md).

## Откат

Остановить новый контейнер. Вернуть зафиксированный прежний commit/образ и прежние настройки окружения/Compose. Старый прототип использовал `family-planner.db`, новый использует `family-planner-v2.db`; старый файл сохраняется. Не направлять старый код на новую схему. При восстановлении из backup использовать отдельное имя файла и настройки из [DATABASE.md](DATABASE.md), не перезаписывать открытую БД. Сохранить новую базу для разбора причин отката.
