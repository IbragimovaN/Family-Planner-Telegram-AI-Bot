# Этап 3: семья, участники и приглашения

## Проверка в браузере

Используйте уже работающий локальный режим на http://localhost:5173. После обновления кода перезапустите backend и обновите страницу. Схема БД на этом этапе не менялась; очищать базу не нужно.

Если запускаете заново, команды из корня `family-planner-bot`:

Первый терминал PowerShell:

```powershell
$env:PORT="3001"
npm run server-dev:auth --prefix server
```

Второй терминал:

```powershell
$env:DEV_API_PORT="3001"
npm run dev
```

1. В обычном окне браузера войдите как «Тестовый пользователь».
2. Назовите семью и нажмите «Создать семью». Вы станете владельцем.
3. Нажмите «Создать приглашение», затем «Скопировать». Сохраните ссылку: после перезагрузки полный токен не отображается повторно.
4. Откройте **новое окно инкогнито** и вставьте ссылку. Нажмите «Войти как второй участник», затем «Вступить в семью». Форма создания семьи и поле кода на этом экране скрыты.
5. Второй профиль должен видеть ту же семью и двух участников. У него нет управления настройками, приглашениями и удалением людей.
6. В первом окне обновите страницу или вернитесь к нему: появится второй участник. Активная страница также обновляет состав каждые 15 секунд.
7. Владелец может изменить название и часовой пояс. Проверьте сохранение после обновления страницы.
8. Владелец может удалить второго участника после подтверждения. Во втором окне после обновления снова появится предложение создать семью или вступить. Уже открытая сессия не даёт права читать прежнюю семью.
9. Владелец отзывает приглашение после подтверждения. Повторная попытка вступить по старой ссылке должна завершиться сообщением о недействительном приглашении.
10. Чтобы ещё раз проверить успешное вступление, создайте новое приглашение. Старая отозванная ссылка остаётся нерабочей.

Два обычных окна одного браузера делят cookie и не подходят для двух пользователей. Используйте инкогнито либо другой браузер. Тестовый и второй профили фиксированы, живут только в явно включённом локальном dev-режиме и недоступны в production.

Временные задачи этапа 2 доступны после создания/вступления по кнопке «Мои дела». Они пока персональные; полноценные семейные списки дел реализуются в этапах 6–7. Вишлисты и профили людей при создании семьи автоматически не создаются.

## Правила

- Пользователь состоит максимум в одной семье. Создание семьи, назначение владельца и пустого списка покупок выполняются одной транзакцией.
- Приглашение многоразовое, действует 7 суток. В БД только SHA-256 токена; полный токен выдаётся владельцу один раз при создании. Список приглашений содержит даты и статус, без токенов.
- Повторное вступление в ту же семью по действующему приглашению не создаёт дубликат. В другую семью вступить нельзя.
- Владелец управляет названием, часовым поясом, приглашениями и удалением обычных участников. Удалить владельца нельзя. Выход из семьи и передача роли не реализованы.
- Удаление участника удаляет только членство. Пользователь, сессии и исторические записи остаются; права на семейные запросы проверяются заново при каждом запросе. По ещё действующей ссылке бывший участник может вступить снова: для запрета нужно отозвать ссылку.
- Часовой пояс по умолчанию `Europe/Moscow`, поддерживаются корректные IANA timezone identifiers; начало недели — понедельник.
- Все семейные ID вычисляются на сервере по пользователю из сессии. Мутации с лишним `family_id` отклоняются, операции над чужим участником/приглашением возвращают 404 либо 403.
- Создание семьи, вступление и создание приглашений ограничены общим лимитом 20 запросов в минуту на пользователя.

## Проверка в Telegram

К настройкам из [AUTH_CHECK.md](AUTH_CHECK.md) добавьте в `server/.env` публичный username бота:

```dotenv
TELEGRAM_BOT_USERNAME=имя_бота_без_собачки
```

Токен бота — отдельная секретная переменная `TELEGRAM_BOT_TOKEN`. Для production-приглашений username обязателен. В BotFather настройте **Main Mini App** этого бота на HTTPS URL приложения: приглашение имеет вид `https://t.me/<bot>?startapp=invite_<случайный_токен>`. Это не обычная ссылка на сайт и не `family_id`.

При открытии через Telegram параметр `tgWebAppStartParam` или `start_param` заполняет форму приглашения. Вступление выполняется только после нажатия кнопки и серверной проверки токена. Сам параметр ссылки не считается подтверждением личности — для этого служит сессия после проверки Telegram initData.

После публикации проверьте сценарий двумя реальными Telegram-аккаунтами: создание семьи, переход по ссылке, вступление, отсутствие прав владельца у второго пользователя, отзыв ссылки и невозможность вступить по ней.

Ссылки Main Mini App и параметры запуска описаны в [документации Telegram](https://core.telegram.org/bots/webapps#launching-the-main-mini-app).

## API

| Метод | Путь | Доступ |
| --- | --- | --- |
| POST | `/api/families` | Пользователь без семьи; `{name, timezone?}` |
| GET | `/api/family` | Своя семья либо `null` |
| PATCH | `/api/family` | Только владелец; `{name?, timezone?}` |
| GET | `/api/family/members` | Любой участник своей семьи |
| DELETE | `/api/family/members/:userId` | Только владелец, кроме удаления владельца |
| GET/POST | `/api/family/invitations` | Только владелец |
| DELETE | `/api/family/invitations/:id` | Только владелец своей семьи |
| POST | `/api/family/join` | Авторизованный пользователь; `{token}` |

DELETE и POST создания приглашения передают `{}`. Для мутаций действуют JSON, Origin и `X-Family-Planner: 1`, как на этапе 2. `GET /api/me` дополнительно возвращает актуальную семью. Полноценные роли не кешируются в cookie.

## Результаты проверки — 1 октября 2026

- 24 автотеста прошли; lint, frontend build/typecheck и backend build/typecheck успешны.
- В Chromium с шириной 390 px и двумя отдельными профилями пройдены создание семьи, приглашение по URL, вступление второго пользователя, отсутствие прав владельца, изменение и сохранение настроек, удаление участника и отказ по отозванной ссылке.
- Production Docker-образ собран. В одноразовом контейнере проверены два входа по подписанным тестовым Telegram-данным, создание семьи, Telegram-ссылка, вступление, запрет изменений обычному участнику и сохранение состава/настроек после перезапуска серверного процесса.
- `docker compose config --quiet` прошёл. Публикация порта 3000 ограничена loopback-интерфейсом; текущие запущенные контейнеры пользователя не менялись.
- Серверные секреты не найдены в frontend-сборке.
- Реальные Telegram-аккаунты и VPS пока не проверены: нужны настройки бота, подключение к VPS и сведения о Caddy. Подготовлен [порядок первого релиза](FIRST_RELEASE.md).

Настройки раскрываются через «Настройки семьи», отзыв приглашений — через «Управление ссылками», удаление — через «Управление участником». Основные действия выделены заливкой, опасные — красным текстом и подтверждением. Выход из аккаунта находится в меню «Аккаунт».

Проверка интерфейса: lint и production-сборка прошли; браузерные сценарии с подменой API проверили приглашение, скрытие второстепенных форм, фокус подтверждения и Escape, отсутствие горизонтальной прокрутки при 320/390/1280 px в светлой и тёмной темах.
