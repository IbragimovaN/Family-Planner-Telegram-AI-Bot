# Этап 5: семейные покупки

## Два раздела

«Список покупок — продукты» сохраняет синий интерфейс, AI, закрытие и историю. Новый розовый раздел «Покупки» — постоянный семейный список без AI/истории/закрытия, с тем же компактным редактированием, удалением и чекбоксами. При каждом входе купленные скрыты, кнопка «Показать все» раскрывает их на прежних местах. Позиции двух разделов хранятся отдельно.

Миграция 4 создаёт таблицу `purchases`. Обновление: `npm run build --prefix server`, затем `npm run db:migrate --prefix server` (с автоматическим backup). API: GET `/api/purchases` возвращает `{list, items}`; POST принимает `{title}`, PATCH `/api/purchases/:id` — `{title?, bought?}`, DELETE — `{}`. Права определяются текущей семьёй из сессии; новые товары идут в конец.

## Что реализовано

Один общий открытый список на семью. Каждый участник может добавить, изменить и удалить позицию, отметить купленное и вернуть его в покупки. В интерфейсе только название (до 200 символов), редактирование прямо в строке, удаление товара без подтверждения. По умолчанию купленные скрыты, кнопка «Показать все» показывает их зачёркнутыми на прежних местах. Отметки не пересортировывают список.

Товары сохраняются сразу в конце списка, без ожидания AI. При наличии хотя бы двух позиций и товаров без категории отдельная сортировка запускается через 10 секунд после выхода из поля ввода. Возврат в поле, новый ввод, редактирование, скрытие вкладки и уход со страницы отменяют таймер/ожидание ответа. После успешной сортировки на две секунды появляется зелёное уведомление «Список отсортирован». Если пользователь ушёл до сортировки, она будет запланирована при следующем открытии списка.

Системный промпт и категории сохранены в `server/src/shopping-ai.ts`. Внутри категории порядок стабилен. При сбое AI товары остаются сохранёнными; бесконечных повторов нет, новая активность позволяет повторить попытку после паузы. Одновременные запросы сортировки одного списка не дублируют вызов AI. Ответ не применяется, если за время запроса список изменили или закрыли, пользователь потерял доступ либо отменил запрос. Изменение схемы БД не требуется. Модель задаётся `SHOPPING_AI_MODEL`, таймаут — 8 секунд, без автоматических повторов.

Ответ классификатора структурирован и проверяется по схеме: https://developers.openai.com/api/docs/guides/structured-outputs. 8 октября 2026 выполнен отдельный реальный smoke-запрос на вымышленных товарах: «Молоко» → 5, «Шампунь» → 0. Это подтверждает доступность настроенного API для этого примера, но не качество классификации всех возможных названий.

После дополнения AI-порядка прошли 36 серверных тестов, lint, обе сборки, typecheck и браузерный сценарий. Локальная миграция 3 выполнена после автоматического backup; на других окружениях её нужно применить отдельно.

Закрытие после подтверждения атомарно сохраняет список в истории и создаёт новый пустой. Сохраняются время и пользователь, закрывший список; даты интерфейс показывает в часовом поясе семьи. История от новых к старым, закрытый список неизменяемый. Любой участник может удалить закрытый список целиком после подтверждения. Удаление каскадно удаляет позиции.

Интерфейс обновляет данные после действий, при возвращении на вкладку и раз в 15 секунд. Если список закрыл другой участник, открытая форма сохраняет текст и предлагает явно добавить его в новый список. Полноценной офлайн-работы нет.

## API

Все маршруты требуют сессии и текущего членства в семье. Для мутаций обязательны JSON, корректный Origin и `X-Family-Planner: 1`. `family_id` не принимается от клиента.

| Метод и путь | Тело / ответ |
| --- | --- |
| GET `/api/shopping-lists/current` | `{list, items, sortingRevision}`; revision равна null, если сортировка не нужна |
| POST `/api/shopping-lists/current/items` | `{listId, title, quantity?, note?}` → 201 `{id, sorting: "pending"}` |
| POST `/api/shopping-lists/current/sort` | `{listId}` → `{sorting: "applied" / "skipped" / "deferred" / "unavailable"}` |
| PATCH `/api/shopping-items/:id` | Непустой набор `{title?, quantity?, note?, bought?}` → 204 |
| DELETE `/api/shopping-items/:id` | `{}` → 204 |
| POST `/api/shopping-lists/current/close` | `{listId}` → `{list, items}` нового/текущего открытого списка |
| GET `/api/shopping-lists/history` | `{lists}` с `itemCount`, `closedAt`, `closedByUserId`, `closedByName` |
| GET `/api/shopping-lists/:id` | `{list, items}` только своей семьи |
| DELETE `/api/shopping-lists/:id` | `{}` → 204, только закрытый список |

`listId` — идентификатор списка, который пользователь видел перед действием. Повторное/одновременное закрытие одного ID не закрывает следующий список. Добавление в устаревший закрытый список возвращает 409, чужие ID — 404. Изменения закрытых позиций возвращают 409. Миграция 3 добавляет `category_rank` и `sort_position`, не меняя миграции 1–2. Перед запуском обновлённого сервера выполнить `npm run build --prefix server` и `npm run db:migrate --prefix server`; CLI автоматически делает согласованный backup. Старые поля quantity/note сохранены для совместимости API, интерфейс их не использует.

## Проверки

Из корня:

```sh
npm run lint
npm run build
npm run build --prefix server
npm run typecheck --prefix server
npm test --prefix server
node scripts/check-shopping-layout.mjs
node scripts/check-shopping-idle.mjs
```

8 октября 2026: все 31 серверный тест прошли. Новые интеграционные сценарии проверяют совместный CRUD, валидацию, complete/reopen, конкурентное и повторное закрытие, историю и её неизменяемость, каскадное удаление, защиту всех маршрутов от анонимов/пользователей без семьи/чужой семьи/удалённых участников и откат всей транзакции при сбое создания нового списка. Браузерный сценарий проверяет UI с временной БД и имитацией Telegram SDK, без реальных токенов.

Для ручной проверки: `npm run server-dev:auth --prefix server` и `npm run dev`. В двух отдельных браузерных профилях войдите тестовыми пользователями и объедините их приглашением. Добавьте покупки одним, обновите список другим, измените количество, отметьте купленное и включите «Показать все». Закройте список, проверьте новый пустой список и неизменяемую историю, затем удалите закрытый список. Отдельно проверьте закрытие вторым пользователем во время заполнения формы первым.

Развёртывание на VPS и приёмка в настоящем Telegram Android/iOS не выполнялись. Порядок развёртывания — `FIRST_RELEASE.md`, с сохранением текущей базы и тома.
